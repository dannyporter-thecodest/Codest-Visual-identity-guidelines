# Case studies: ruleset and converter

This folder is everything Cody (or any AI agent) needs to convert The Codest's case studies into the new case study format and build each one as a page in the design system.

The format copies The Software House (tsh.io) case studies: their section order, section sizes and title formulas. The Codest's own rules sit on top (no invented facts, statistics carried over, verbatim quotes, blocked clients).

## Read in this order

| # | File | What it settles |
|---|---|---|
| 1 | `rules/01-format.md` | The 10 sections, their order, word counts and page layout |
| 2 | `rules/02-titles.md` | Title formulas and title checks |
| 3 | `rules/03-writing-register.md` | Tone: formal, precise, professional. Examples of what to avoid |
| 4 | `rules/04-statistics.md` | Where statistics go, and what to do when there are none |
| 5 | `rules/05-hard-rules.md` | Rules that are never broken |
| 6 | `rules/06-conversion-mapping.md` | How each old thecodest.co section maps to the new format |
| 7 | `rules/07-checks.md` | The self-check before handing anything back |
| 8 | `examples/estimote/` | A finished, approved conversion to copy the standard from |

## Outcomes: what every conversion must produce

For each case study, one folder `case-studies/output/<slug>/` with:

| File | What it is | Who uses it |
|---|---|---|
| `source.md` | The old page's text, copied as is (headline, every section, stats, quote) | Proof of where each fact came from |
| `content.json` | The new case study as data, following `templates/content.schema.json` | Input to the build |
| `case-study.md` | The new case study as plain text | Sent to the client for sign-off |
| `page.html` | The case study page built from the design system | Web team, review |
| `report.md` | Statistics carried over, facts left out, questions for Delivery, build warnings | Danny, Delivery |

`case-study.md`, `page.html` and `report.md` are generated by the build. Cody writes only `source.md` and `content.json`.

A conversion is **done** when the build reports `0 errors`, every warning is fixed or explained in `report.md`, and the page has been looked at at 1440px and 375px.

## Workflow for one case study

1. **Copy the source.** Open the old page and copy its text into `output/<slug>/source.md`: headline, hero facts, every section, every statistic (headline, stats band, results, FAQ), the quote with name and role.
2. **Write `content.json`.** Start from `templates/content.example.json`. Follow the rules files. Use only facts in `source.md`.
3. **Fill the report fields** in `content.json`: every statistic found in the source (`report.source_statistics`), the quote exactly as on the source (`report.source_quote`), facts left out, questions for Delivery.
4. **Build:** `node case-studies/build.js case-studies/output/<slug>/content.json`
   Add `--shot` to save screenshots at 1440px and 375px (needs Playwright, as in `creatives/`).
5. **Fix every error and warning.** Errors block the case study. Warnings must be fixed or explained.
6. **Look at the page** next to `examples/estimote/page.html` and `design-system/reference/case-study-detail.png`.
7. **Update `inventory.json`**: set the case to `converted` and add the slug.

## Converting all of them

`inventory.json` lists every live case study on thecodest.co (21 when this folder was made). `CODY_TASK.md` is the prompt to run the whole batch.

## Files

```
case-studies/
  README.md                 this file
  CODY_TASK.md              the prompt for the batch conversion
  inventory.json            every case study, its URL and status
  build.js                  checks content.json and builds case-study.md, page.html, report.md
  rules/                    the ruleset (read in order)
  templates/
    content.schema.json     the shape of content.json
    content.example.json    a blank to start from
    case-study.md           the plain text skeleton
    case-study-page.html    the page template (design system components)
  examples/estimote/        the reference conversion (content.json and its built outputs; converted before source.md was part of the workflow)
  output/<slug>/            one folder per converted case study
```
